## 0. 五分钟读懂 AIDBM

**一句话**：AIDBM 帮你在**不给数据库服务器装任何软件**的前提下，完成数据备份、恢复、验证和再利用。

**它做到的三件事**

| 你关心的事 | AIDBM 的做法 |
|---|---|
| 不想在被保护的机器上装东西 | 全程走 SSH + 数据库自带命令（`mysqldump`/`RMAN`/`pg_dump`…）；物理备份的第三方工具由平台临时推送、用完即清（**零客户端安装**） |
| 备份了到底能不能恢复 | 「恢复校验」定期自动做**真实**恢复验证（不是读一下文件头就报成功），「数据对比」再比行数与校验和 |
| 机器多了、数据多了管不过来 | 备份策略（RPO/RTO 分级）+ 巡检 + 智能告警 + 保留策略定期清理 |

**一条完整的数据保护闭环**

```
建任务（备份） → 备份记录（看成功/失败）
      ↓                     ↓
定期恢复校验（证明能恢复） → 数据对比（证明恢复的数据是对的）
      ↓
出问题 → 数据恢复 / PITR 任意时间点恢复 / 克隆一份出去做测试
```

**先记住三个入口就够了**
- **数据库备份**：配定期备份任务（日常 90% 的工作在这里）
- **数据恢复**：真要恢复时来这里
- **备份记录**：查某次备份是否成功、产物在哪

## 1. 开始之前

### 1.1 登录

浏览器打开 `http://<平台地址>:8080/login`，填用户名、密码。

> 默认管理员：`admin` / `admin123`。**首次登录后请立刻改密码**：用户管理 → 对应用户右侧「密码」按钮（可同时勾选「下次登录必须修改密码」）。

### 1.2 界面速览

左侧菜单分 6 组（看不到某个菜单 = 当前账号没这项权限，找管理员开）：

| 分组 | 菜单 |
|---|---|
| 概览 | 仪表盘 |
| 备份管理 | 数据库备份、文件备份、对象存储备份、存储管理、备份策略、无 Agent、备份插件、实时备份 |
| 数据恢复管理 | 数据恢复、恢复校验、数据对比、数据库部署 |
| 记录 | 备份记录、恢复记录 |
| 灾备管理 | 数据迁移、数据同步、容灾链路、克隆服务、虚拟机备份 |
| 运维 | 运维运营分析、巡检、AI 智能助手、智能告警、数据价值挖掘、系统日志、系统设置、用户管理 |

页面右上角/表头常见三个按钮：**新建**（建任务）、**刷新**（重新拉取数据）、**导出**（CSV/Word/PDF 或诊断包）。

### 1.3 第一步建议：纳管 SSH 主机（重要）

大多数远程数据库、文件备份都依赖 SSH 通道（平台通过 SSH 在目标机上执行数据库自带命令，不装任何东西）。

操作：**文件备份** 页 → SSH 主机区域 → 新增主机，填写：主机名称、系统类型（Linux/Windows）、主机地址、端口、用户名、认证方式（密码 / 私钥）、备注。

> 平台与被备份数据库**在同一台机器**时不用纳管，任务留空即可自动走本机通道。
> 也可以不纳管，在任务的「高级选项」里直接填 SSH 地址/账号/密码（`t_ssh_addr` 等），二者二选一。

## 2. 我要做什么 → 用哪个功能（速查表）

| 我的需求 | 去哪个菜单 | 关键动作 |
|---|---|---|
| 每天 2 点自动备份某数据库 | **数据库备份** | 新建任务 → 备份方式/类型/调度/保留天数 |
| 备份整台机器的目录或文件 | **文件备份** | 新建任务 → 源路径（本地/远程）+ 目标路径 |
| 备份 MinIO / OSS / COS 桶 | **对象存储备份** | 桶级保护，桶侧零安装 |
| 要求秒级 RPO、能回到任意一秒 | **实时备份** | 开 CDC/日志流，用 PITR 时间轴恢复 |
| 数据被误删/库坏了，要恢复到原库 | **数据恢复**（恢复类型：数据库） | 选备份记录 → 选目标 → 执行恢复 |
| 误删一批数据，只想恢复到删除前那一刻 | **备份记录** → PITR | 填目标时间点 → 开始恢复 |
| 只要某几张表的数据 | **备份记录** → 对象级恢复 | 填 bucket/前缀/键 → 开始恢复 |
| 不确定备份能不能真的恢复 | **恢复校验** | 新建校验策略（可设为定期自动） |
| 不确定恢复出来的数据对不对 | **数据对比** | 源库 vs 恢复库：表 → 行数 → 校验和 → 抽样 |
| 要用备份数据跑测试/开发，别动生产 | **克隆服务** | 选备份记录 → 立即克隆 → 用完后销毁 |
| 要换库/搬迁数据 | **数据迁移** | 向导：预检查 → 迁移 → 校验 → 报告 |
| 要长期双写/准实时同步 | **数据同步** | 源 Reader → 目标 Writer，支持字段映射与增量 |
| 想知道备份有没有在跑、有没有失败 | **仪表盘**、**巡检**、**备份记录** | 看健康度/最近记录/巡检报告 |
| 想让平台主动提醒风险 | **智能告警** | 配六类阈值 + 通知开关 |
| 备份失败要查原因 | **系统日志** | 导出诊断包给支持人员 |
| 备份占满磁盘 | **数据库备份 → 定期清理**、**存储管理** | 按各任务的保留天数清理过期产物（可先扫描预览） |
| 给同事开账号、限制他能点什么 | **用户管理** | 新增用户 → 选角色/权限 |
| 缺 mysqldump/xtrabackup 等工具 | **备份插件** | 一键安装所需依赖；也可上传/测试 JDBC 驱动 |

## 3. 核心场景：手把手操作

### 3.1 场景一：给一个 MySQL 库做每天自动备份

**入口**：左侧「数据库备份」→ 右上「新建任务」

**Step 1 — 基本信息（必填项已标 `*`）**

| 字段 | 怎么填 | 说明 |
|---|---|---|
| 业务系统 `*` | 如「财务系统」 | 用于按业务归类，报表和筛选都用它 |
| 任务名称 `*` | 如「财务-MySQL-每日全量」 | 建议包含对象+频率 |
| 数据库类型 `*` | MySQL / MariaDB / PostgreSQL / Oracle / kingbase(金仓) / DM(达梦) / SQL Server / Redis / MongoDB / Neo4j | 选错会导致命令不匹配 |
| 备份方式 `*` | **逻辑备份（推荐）** / 物理备份 / 自定义脚本 | 逻辑=库自带导出命令，通用；物理=整库文件级，快但要工具支持；自定义=你自己的脚本 |
| 备份类型 `*` | 全量备份 / 增量备份 / **组合（全量+增量）** | 组合=全量每周几 + 增量每周另外几天 |
| 主机地址 `*` / 端口 `*` | 数据库地址与端口 | |
| 用户名 / 密码 | 数据库账号 | 建议专用备份账号，权限够导出即可 |
| 数据库/实例名 | 留空 = 全实例（备份所有库） | |
| 调度（cron） | 如 `0 2 * * *` = 每天 2:00 | 也可用「每天/每隔N分钟」的间隔方式 |
| 备份文件格式 | 按需要选择默认即可 | |

**Step 2 — 选了「组合」时**：分别勾选**全量调度（按天）**和**增量调度（按天）**的星期，并各自填一个执行时间（如全量周日 02:00、增量周一至周六 02:00）。

**Step 3 — 高级选项（按需，不必全填）**

| 字段 | 建议 |
|---|---|
| 保留天数 | 建议改。决定这份备份多久后可被自动清理，**默认 30 天**（见 §4.1） |
| 已纳管 SSH 备份机 | 远程库选它；或在下面直接填 SSH 地址/端口/用户/密码 |
| 流量控制（限速）、压缩级别 | 生产环境建议限速，避免影响业务 |
| 存储池加密 / 加密密码 | 涉敏库建议开启（在系统设置里配 KMS） |
| 执行超时 / 空闲超时 / 失败重试次数 / 失败重试间隔 / 断点续传 | 大库建议开重试与断点续传 |

**Step 4 — 类型参数（JSON，可选）**
例如给 mysqldump 追加参数：`{"extra_args": "--set-gtid-purged=OFF"}`
自定义脚本模式下，`备份脚本`、`产物目录`、`超时秒数` 在该页填写。

**Step 5 — 保存后立刻验证一次**
任务列表 → 该行「**备份**」按钮（立即执行一次）→ 去「备份记录」看是否 success。**没跑成功过的备份不算备份**，务必先手工跑一次。
列表每行还有「编辑」「删除」；已停用的任务会显示灰色「已停用」徽章。

> 常见问题：编辑不了任务、点「编辑」没反应？这是历史缺陷（组合任务），已修复；若仍异常，页面会直接弹出红色错误提示，请把提示内容发给支持人员。

### 3.2 场景二：备份服务器上的目录 / 文件

**入口**：左侧「文件备份」→ 新建任务

- **源类型**：本地目录 / 远程主机（SSH，无 Agent）
- **源路径**：每行一个目录或文件路径
- **排除规则**：每行一个，支持通配符（如 `*.log`、`/tmp/**`）
- **目标类型 / 目标路径**：备份产物落到哪里（本地目录或远程 SSH 主机）
- **备份类型**：全量 / 增量 / 组合（全量+增量），组合时分别勾春天数和填时间
- **保留天数**、**限速**、**压缩级别**的用法与数据库备份任务相同
- 该页同时维护 **SSH 主机**列表（见 §1.3）

### 3.3 场景三：数据误删了，要恢复

**入口**：左侧「数据恢复」

1. **选恢复类型**：数据库 / 文件 / 对象存储
2. **选备份记录**（下拉可按时间选择）；卡片会显示该记录的来源、时间、大小、是否已校验
3. **选恢复到哪里**
   - **恢复回原实例**：选「恢复到原机」，最常用（覆盖前请确认）
   - **跨主机恢复**：选「跨主机」，然后选择**已纳管的 SSH 主机**，或填直连信息（目标主机/端口/用户/密码）
   - **文件恢复**：填目标目录 + 目标主机
   - **对象恢复**：填 bucket、前缀、对象键（可多行）、同名覆盖策略（仅覆盖较新的 / 总是覆盖 / 跳过已存在；可选是否应用删除）
4. **点「执行恢复」**，进度条显示执行状态；结果在「恢复记录」页可追溯

**只想要某个时间点的数据**：去「备份记录」页 → 该记录 → **PITR** → 填目标时间点 → 开始恢复（需要有对应的日志流/实时备份才能精确到秒）。

### 3.4 场景四：证明备份真的能恢复（强烈建议配置）

**入口**：左侧「恢复校验」

1. 点「新建校验策略」，填：策略名称、**关联任务**、调度方式（cron 或间隔分钟）、是否启用、克隆副本保留时长（分钟）、恢复资源池
2. 保存后会按你设的频率**自动真实恢复**一次（把备份拉起到独立的隔离环境中完整还原，不是只读一下文件头）
3. 页面下方显示每次校验报告，顶部有「策略数 / 成功 / 失败 / 最近校验」四个统计卡

**再进一步**：「数据对比」把恢复出来的库和源库做表清单 → 行数 → 校验和 → 抽样行的比对。

### 3.5 场景五：拿备份数据搭测试库（不动生产）

**入口**：左侧「克隆服务」→「立即克隆」

1. 选择源备份记录（可搜索）
2. 填：目标环境、目标主机、目标库口令、申请人/用途备注
3. 点立即克隆 → 状态自动刷新（creating → ready）
4. ready 后页面上会给出**连接串**（host:port/db），直接用；用完后点销毁释放资源

> 默认免审批直通；不支持的产物（如物理 tar）会明确报失败原因，不会给你一个假的"成功"。

## 4. 日常运维：让平台自己管起来

### 4.1 定期清理（磁盘的日常腾位）

**入口**：数据库备份页 → 工具栏黄色按钮「**定期清理**」

- **开关**：是否每天自动清理（默认开启）
- **清理时间（cron）**：默认 `10 3 * * *`（每天 03:10），可改
- **每任务最少保留**：兜底份数（默认 1）——**每个任务最近 N 份成功备份无条件保留**，永远不会把最后一个可用备份删掉
- **清理后处理**：勾选=连备份记录一起删；**不勾选=记录标记为「已清理（过期）」**保留审计轨迹（推荐）
- 建议流程：先点「**扫描预览**」（只看不动手）→ 确认清单和释放的空间无误 → 再点「立即清理」

**判定依据**：每个任务自己的**保留天数**（默认 30 天）。没设保留天数的任务**不会**被自动清理，不会被误伤。
任务数据里还有一个「保留份数」字段（部分历史任务 / 接口创建时带入），清理时也会按份数判定；但当前任务表单未提供该输入框，需要时由管理员通过接口设置。
预览里若出现「产物已不在磁盘」的说明，表示这些是历史遗留的幽灵记录（文件早被人工删了），清理只是把账本对齐，不虚报释放空间。

### 4.2 仪表盘（每天看一眼）

显示：受保护对象数、任务数、备份量、健康度、风险项、下次执行、最近记录、容量、趋势图等。页面顶部有三个快捷按钮：**新建备份任务 / 发起恢复 / 恢复演练**。

### 4.3 巡检

- 点「立即巡检」做一次体检：连通性、调度、最近运行状态
- 「保存并生效」可设 cron 让它自动跑
- 报告支持导出 **CSV / Word / PDF**，直接交托给汇报对象

### 4.4 智能告警

预测六类风险：**备份失败、数据验证失败、存储不足、链路劣化、演练超期、RPO 突破**。
每项配阈值 →「保存配置」→ 开启通知；点「立即分析」看当前预测结果。邮件通知在系统设置里配 SMTP。

### 4.5 系统日志

三个页签：**系统日志 / 操作日志 / 平台运行日志**，可按级别、任务、记录筛选。
出故障时点「**导出诊断包**」，把它发给支持人员即可；「清理过期」可清理历史日志。

### 4.6 存储管理

- **本地存储位置**：查看容量/已用，可「修改存储位置」（变更时会提示是否迁移数据）
- **三重备份体系**：L1 MinIO 热数据 → L2 S3 冷数据 → L3 源端本地路径导出；可「新增存储目标」「测试连接」
- **复制策略**：配 L1→L2→L3 的复制时机、重试次数与间隔
- **冷热分级生命周期**：配 L1→L2、L2→L3 的迁移天数与保留时长、到期天数，可「立即执行」

### 4.7 备份策略（按业务重要程度分级）

「备份策略」页可建策略：等级（核心 / 重要 / 一般）、RPO、RTO、保留期、备份方式、链路策略，并可**绑定到具体任务**（支持按等级填充默认值、批量勾选绑定）。适合规范多团队任务的场景。

### 4.8 备份插件

若某类备份缺少客户端工具（如物理备份缺 xtrabackup），来这里 **「一键安装所需」**（安装只在平台侧或按理论推送到临时目录执行后清理，不在被管机器常驻）。该页还能**上传 JDBC 驱动并测试连接**，并显示已安装/可安装统计与 JVM 状态。

### 4.9 用户与权限（管理员）

「用户管理」→ 新增用户：用户名、显示名、邮箱、密码、角色、权限勾选、是否启用、是否强制下次改密。
菜单与按钮都带权限控制，看不到某功能就是没授权。

### 4.10 系统设置

可配：**邮件通知（SMTP）**、AI 告警/模型配置、加密密钥（KMS，可测连通性）、**重新加载调度**（改完 cron 后若想立刻生效可点它）。

## 5. 进阶 / 专项场景

| 场景 | 菜单 | 说明 |
|---|---|---|
| 搬迁到新库 | 数据迁移 | 一站式向导：预检查（探测源/目标、自动建库、统计对象）→ 结构+全量迁移 → 逐表行数校验 → 迁移报告。**不停机增量迁移请用「数据同步」** |
| 长期数据同步 / 准实时同步 | 数据同步 | Reader → 统一类型 → Writer，支持字段映射与增量 |
| 整机灾备 | 虚拟机备份 | 整机 CEP：恢复点（PITR）、永久增量、合成全量、原位还原、克隆为新 VM、自动恢复验证 |
| 两地多活 / 多线路 | 容灾链路 | HA 双运营商专线智能选路、日志间隙自动填补、备端只读一致性校验 |
| 演练合规 | 容灾演练 | 演练—评估—改进闭环（可从仪表盘「恢复演练」进入） |
| 准备演练/测试环境 | 数据库部署 | 在新建空机器上部署数据库实例 |
| 合规与数据资产治理 | 数据价值挖掘 | 资产盘点 → 敏感发现与分级 → 价值评估与治理 → 合规概览 → 脱敏外发 |
| 桶里的海量非结构化数据 | 对象存储备份 | MinIO / OSS / COS / S3 兼容，桶级保护，桶侧零安装 |
| 想确认"到底有没有在目标机留东西" | 无 Agent | 按任务展示本次走了哪条通道、最高侵入到哪一级，并可对纳管主机做只读取证、验证目标端零残留 |
| 想要 RPO 秒级 | 实时备份 | 日志流式捕获 + CDP 恢复点时间轴，支持恢复到任意时间点 |

## 6. 出故障了怎么办（排查顺序）

```
任务列表「上次运行」显示失败
   ↓ 点「备份记录」看该次记录的状态与错误信息
   ↓ 点该记录「详情」：可看到备份文件路径、SHA256 校验和、耗时，以及完整执行日志（支持一键复制到剪贴板）
   ↓ 仍有疑问 → 「系统日志」→ 导出诊断包
```

**常见原因对照表**

| 现象 | 先查这里 |
|---|---|
| 连不上数据库 | 主机/端口/用户名/密码是否正确；数据库限权来源 IP；远程是否需通过 SSH 主机纳管 |
| 提示找不到 mysqldump / RMAN 等命令 | 「备份插件」页装或补依赖；或在任务「高级选项 → 备份命令所在目录」手填工具 bin 目录 |
| 提示权限不足、备份出 0 字节文件 | 备份账号是否具备导出权限；产物目录是否对该账号可写 |
| 远程时不时连不上 | 纳管主机 + 重试设置（失败重试次数/间隔）；网络抖动 |
| 磁盘写满 | 「存储管理」看容量；用「定期清理」按保留策略腾空间 |
| 组合/增量任务不按天跑 | 编辑任务时确认勾选了对应「按天」+ 时间；保存后列表刷新确认 cron 已生效 |
| 页面某按钮点了没反应 / 报错 | 页面会弹红色提示（含原因），截图发支持人员；也可先从系统日志定位 |

**重要的使用原则**
1. **新建任务后先手工跑一次**，确认 success 再交给调度。
2. **至少配一条恢复校验策略**——没有验证过的备份不算保护。
3. **定期清理请先看预览**：「保留天数」是它的依据，「每任务最少保留」是最后一道保险（默认 1 份，永不清空最后一个可用备份）。

## 7. 常见问题 FAQ

**Q：需要在数据库服务器上安装 Agent 吗？**
不需要。平台通过 SSH 调用目标机已存在的数据库自带命令；第三方工具（如 xtrabackup）也是备份时临时推送到临时目录执行、用完清理，目标机不留驻任何进程。可用「无 Agent」页做零残留取证验证。

**Q：平台能离线使用吗？**
可以，这是它的设计前提：不依赖公网安装任何东西，所有依赖随平台自带。

**Q：备份数据存在哪？**
默认在平台本地备份根目录下按 `<类型>/<任务>_<任务名>` 归档；可配 MinIO/S3 等多级存储目标（见 §4.6）。

**Q：恢复到生产库安全吗？**
恢复是**覆盖式**操作，务必确认目标实例与时间点，建议先在「克隆服务」拉一份隔离副本验证数据，再决定是否覆盖生产。

**Q：为什么有些记录显示「已清理（过期）」？**
说明它的产物已按该任务的保留策略被定期清理了。这是保留审计轨迹的正常状态（记录还在、文件已删/已失），不是备份失败。

**Q：为什么继承的任务、导入的任务的子调度和我填的不一样？**
如果任务只有 cron 而没有「按天」配置（如 CSV 导入或旧版本创建），编辑时会从 cron 的星期段自动反推勾选；保存时会按你勾选的天数重新生成 cron，请以保存后列表显示的为准。

**Q：能不能限制某个同事只能看不能操作？**
可以，用户管理里按需勾选权限；菜单与按钮都做了权限控制。

## 8. 名词小表

| 名词 | 含义 |
|---|---|
| 逻辑备份 | 用数据库自带导出命令（mysqldump/pg_dump/expdp 等）导出数据，通用、可跨版本 |
| 物理备份 | 直接复制数据库的物理文件，速度快，恢复需同环境 |
| 全量 / 增量 / 组合 | 全部数据 / 只备份变化部分 / 两者按不同星期组合 |
| RPO | 允许丢失的数据时间窗口（如 15 分钟） |
| RTO | 从故障到业务恢复所需时间 |
| PITR | 任意时间点恢复（Point-In-Time Recovery） |
| CDC | 变更数据捕获，实时备份的基础 |
| 克隆 / VDB | 从备份快速拉起一份隔离的可用数据库副本 |
| 冷热分级 | 备份从热存储 L1 逐步迁移到冷存储 L2 / L3 或归档的策略 |
| 幽灵记录 | 备份记录还在、产物文件已不在磁盘（例如被人工删除），清理时只标注、不虚报释放空间 |

如果在平台里找不到某个能力，或者发现了异常行为：
1. 记录当时的菜单路径、任务名称、报错原文；
2. 到「系统日志 → 导出诊断包」取下诊断信息；
