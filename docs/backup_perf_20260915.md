# 大库备份性能优化与断点续传（2026-09-15）

现场问题：10GB 库在同机备份，网卡流量只有 **600KB/s**，跑到 1.4GB 后被 **3600s 超时**砍掉，
重试又从 0 开始，永远跑不完。

## 1. 根因定位

`core/engines/file.py` 的 SSH 数据通道（所有远程 dump / tar 流的唯一入口）有三个叠加的性能坑：

| 坑 | 代码 | 后果 |
|---|---|---|
| **O(n²) 内存拷贝（主因）** | `out += sess.recv(65536)` | `bytes` 不可变，每追加 64KB 都要把**已有全部数据** memcpy 一遍。累积到 1.4GB 时单次追加要复制 1.4GB，有效吞吐直接掉到几百 KB/s——**数据量越大越慢**，与现场完全吻合 |
| 每轮只读 64KB + 无数据固定 `sleep(0.05)` | 主循环 | 等效限速约 1.3MB/s；循环次数与系统调用开销成倍增加 |
| 全量产物先攒在内存再落盘 | `remote_db_dump()` 返回 bytes | 10GB 库 → 10GB 内存/交换，爆内存风险 |
| 附带：写死 `timeout=3600` | 各 dump 调用点 | 大库必然被打断，且重试＝从头重跑（管道没有 offset 语义） |

## 2. 修复

1. **统一重写数据通道** `_ssh_exec_stream()`：
   - 支持 `out_file`/`out_path`：**边收边写盘**，内存恒定（256KB 块），不再攒在内存；
   - 单次 `recv` 256KB；**仅在无数据时** sleep 2ms（数据充足时不休眠）；
   - SSH 传输窗口 2MB → 16MB、单包 32KB → 128KB（高带宽/高 RTT 链路不再等 window adjust）；
   - `timeout=0` 表示不限总时长；新增 `idle_timeout` 只在"长时间无数据"时判失败（区分大表读得慢与真卡死）；
   - 平台侧限速 `rate_kbps`（不再要求数据库服务器安装 `pv`，符合零安装约束）；
   - 每 30s 输出进度（已传大小 + 速率 MB/s）到操作日志。
   - 新增 `_ssh_exec_pipe_to_file()`（落盘版）；旧 `_ssh_exec_pipe()` 保留兼容，内部改用 `bytearray` 消除 O(n²)。
2. **断点续传**（MySQL/MariaDB 逻辑备份）：远端后台 dump 落盘（`setsid nohup`，SSH 断开也继续）
   + 平台按 offset 增量拉取（边导出边传）。中断/超时/平台重启后**从已传字节继续，不重跑 dump**。
   - 断点元数据：`<产物目录>/.resume_t<任务id>_<db类型>.part{,.meta}`，默认保留 12h（`BACKUP_RESUME_TTL`）；
   - 成功后自动清理远端暂存（`BACKUP_REMOTE_STAGE`，默认 `/tmp/bk_stage`）与本地半成品；
   - 关闭方式：任务高级选项「断点续传」取消勾选（关掉后回退到旧的 stdout 直传通道）。
3. **任务级高级选项**（存 `extra_options`，全局默认可用环境变量覆盖）：
   `cmd_timeout`（默认 0=不限）、`idle_timeout`（默认 1800s）、`retry_interval`（默认 60s）、
   `retry_max`（默认 3）、`resume_enabled`（默认开）。
4. **修复误判**：`remote_has_tool()` 另起 SSH 连接失败时会被当成"没装 zstd"，导致大库备份白白丢掉压缩；
   改为用当前连接 `command -v zstd` 探测。

## 3. 实测对比（平台机 ↔ 数据库机 同机 SSH，dd 输出 N MB）

| 数据量 | 旧实现 | 新实现 | 提速 |
|---|---|---|---|
| 100 MB | 110.5 s（0.9 MB/s） | 2.0 s（50.5 MB/s） | **55×** |
| 150 MB | 249.1 s（0.6 MB/s） | 2.2 s（68.6 MB/s） | **113×** |
| 300 MB | 17 min 仍未传完 | 秒级 | — |

> 旧实现速率随数据量单调下降（0.9 → 0.6 MB/s），正是 O(n²) 的特征；
> **现场测到的 600KB/s 与 150MB 档完全吻合**，可确认同一根因。

### 断点续传验证（MySQL 5.7，52 万行 / 270MB 库）

1. 限速 100KB/s 启动备份，传到 **208,896 字节** 时 `kill -9` 平台进程；
2. 重新执行 → 日志 `命中断点续传`，`续传=True`，**1.4s 完成**（未重跑 mysqldump）；
3. 产物 1,057,025 字节，解压后 270,994,317 字节，含完整 52 万行数据与
   `-- Dump completed on ...` 结尾标记；
4. 完成后本地 `.part/.meta` 与远端暂存文件均已自动清理。

### 引擎层端到端

`MySQLEngine.backup(FULL)` → `success=True`，产物
`.../mysql/8888_e2e_bigdb/20260915_120008__e2e_bigdb__full.sql.zst`，1.0MB（zstd），
message：`通过 SSH 在数据库服务器(root@127.0.0.1:22)执行 mysqldump 成功 | 1.0 MB`。

## 4. 生产建议

- 10GB 以上库：**执行超时保持 0（不限）**，靠「空闲超时 1800s」兜底，避免被时间打断后从头重跑；
- **务必开启断点续传**——任何中断都能续，这是大库能否跑完的分水岭；
- 若远端 `/tmp` 空间不足，可通过 `BACKUP_REMOTE_STAGE` 指定其他暂存目录（需能容纳压缩后产物）；
- 需要限速时在任务「流量控制」填 KB/s，平台侧实现，不要求数据库服务器装任何工具。
